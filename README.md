# Photo Recovery 0.7

Установщик: `release/PhotoRecovery-0.7-Setup.exe`. Запускайте с ярлыка Photo Recovery.

Исправлены цвета и состояния вкладок, потеря списка при лимите NTFS и
накопление посторонних каталогов при поиске выбранной папки.
Подробнее: [V07-REPORT.md](V07-REPORT.md).

Выберите диск слева, раскройте нужную папку или нажмите «Выбрать папку…».
«Сканировать» показывает удалённые записи и ничего не сохраняет. Для прямого
чтения диска подтвердите запрос Windows на доступ администратора.

Выберите найденные файлы / папки и нажмите «Восстановить выбранное» или
«Глубоко восстановить». Путь сохранения заполнен автоматически и доступен
для изменения внизу окна. Папка создаётся при восстановлении. Сохранять на
исходный физический диск нельзя; для восстановления с C нужен другой носитель
или подходящее сетевое расположение. Общий поиск и восстановление всего диска
доступны в меню «Инструменты». Подробнее: [V06-REPORT.md](V06-REPORT.md).

## Предыдущая версия 0.5

Установщик: `release/PhotoRecovery-0.5-Setup.exe`. Он обновляет установленное
приложение и ярлыки на рабочем столе и в меню «Пуск». Python отдельно не нужен.

1. Выберите диск или раздел в верхнем списке либо откройте образ RAW/DD/IMG.
2. Для прямого чтения нажмите «Доступ к дискам: администратор» и подтвердите UAC.
3. Нажмите «Показать удалённые файлы и папки». Разверните дерево или найдите запись
   по имени / пути. Существующие родительские папки также видны для навигации.
4. Выберите файл, папку или несколько записей с Ctrl/Shift. Нажмите
   «Глубоко восстановить выбранное» либо включите «Выбранные файлы / папки»
   и нажмите «Начать поиск» для извлечения по сохранённым записям.
5. Укажите существующую папку на другом физическом накопителе. Вывод на исходный
   физический диск блокируется, даже если выбрана другая буква его раздела.
6. Режим «Весь диск» проверяет записи файловой системы и при включённом поиске
   по секторам дополнительно ищет JPEG/PNG/WebP без имён и папок.

Все типы файлов извлекаются по доступным записям NTFS/FAT32/exFAT, без обещания
целостности содержимого. Крупные обычные файлы читаются блоками до 1 МиБ, лимит
задаётся в интерфейсе (по умолчанию 4096 МиБ, максимум 16384 МиБ). Сохраняются
структура выбранных папок, исходные адреса и SHA-256 в `report.jsonl`.

**Глубокий режим выбранного файла** дополнительно проверяет baseline JPEG, PNG,
обычные ZIP и Office в ZIP (DOCX/XLSX/PPTX). Если сохранённое размещение не даёт
проверяемый контейнер, выполняется ограниченная сборка фрагментов около известного
начала файла. Изображения используют проверки потока/CRC, ZIP — CRC всех элементов.
Окно по умолчанию 2 МиБ; можно увеличить до 32 МиБ. Сохраняются альтернативы,
отмечаются исчерпание бюджета и отсутствие подтверждённой сборки. Размер полной
сборки должен совпасть с размером из записи файла. Общий поиск по диску при
выборе конкретных записей отключён: соседние найденные файлы не выгружаются.

Для остальных типов доступно извлечение по размещению с отметкой
«Файл: целостность не проверена». Универсальная сборка любого повреждённого
формата не реализована. Не восстанавливаются перезаписанные байты; также не
поддержаны сжатые/зашифрованные/sparse-потоки NTFS, зашифрованные ZIP и сборка
ZIP64. При утрате цепочки удалённой папки FAT32 доступны записи её первого
кластера. Утраченные пути показываются отдельно, без выдуманной принадлежности.
Живой раздел может меняться другими программами во время чтения; это не снимок.

Проверки и ограничения выпуска: `benchmark/V05-REPORT.md`.

CLI из установленной папки приложения (терминал администратора для устройства):

```powershell
.\CLI\PhotoRecoveryCLI.exe --list-devices
.\CLI\PhotoRecoveryCLI.exe '\\.\E:' --list-deleted
.\CLI\PhotoRecoveryCLI.exe '\\.\E:' 'D:\Recovered' --select 'ID_ИЗ_СПИСКА' --deep --all-types --search-mib 16 --max-mib 4096
```

Сборка исходников: `powershell -File build-windows.ps1`, затем
`powershell -File installer/build-installer.ps1`. Тесты:
`python -m unittest discover -s tests -v`.

## Предыдущая версия 0.4

Обычная установка Windows: запустите `release/PhotoRecovery-0.4-Setup.exe`.
Мастер на русском устанавливает приложение для текущего пользователя и создаёт
ярлыки на рабочем столе и в меню «Пуск». Python отдельно не нужен.
Удаление доступно в списке установленных приложений Windows.
Сценарий сборки установщика: `installer/build-installer.ps1`.

Версия 0.4 добавляет ограниченный подбор JPEG из 3–5 частей, разделённых
длинными однообразно заполненными промежутками на выбранной границе кластера,
без обязательной карты ddrescue. Сохраняются исходные диапазоны каждой сборки;
точность структуры не означает доказанную подлинность. Альтернативы сохраняются.
В `fragment_search` журнала отдельно измеряются чтение окна, поиск и валидация.
Ускорен разбор коротких кодов Хаффмана; проверка эквивалентности лежит в тестах.

Готовые EXE: `dist/PhotoRecovery/PhotoRecovery.exe` и
`dist/PhotoRecoveryCLI/PhotoRecoveryCLI.exe`. Портативный архив и отчёт находятся
в `release/` и `benchmark/V04-REPORT.md`. EXE включают Python, Pillow и Tcl/Tk.
Для сборки из исходников: `powershell -File build-windows.ps1`.

Новые возможности не охватывают произвольную фрагментацию, progressive JPEG,
HEIC/RAW и восстановление сеанса. Прямое чтение физических дисков не поддерживается.
Частичные JPEG могут содержать заливку декодера; она не считается восстановленными
пикселями. Независимая миниатюра без метаданных происхождения не может быть надёжно
отличена от маленькой самостоятельной фотографии по одному размеру.

Локальное приложение для восстановления фотографий из посекторных образов и поиска уцелевших копий. Интерфейс на русском. Образы открываются для чтения. Каждый запуск создаёт отдельную папку результатов с журналом `report.jsonl`.

## Запуск на Windows 11

1. Распакуйте архив на исправный диск. Для запуска нужен Python 3.11 или новее с компонентом Tcl/Tk, который входит в обычный установщик Python для Windows.
2. Откройте `start-windows.cmd`. При первом запуске скрипт скачает зависимость Pillow в папку проекта.
3. Укажите несжатый посекторный образ диска или раздела (`.raw`, `.dd`, `.img`). Укажите папку для результатов на другом физическом накопителе, если оригинал ещё подключён.
4. При наличии локальных резервных копий или сохранённого кэша Windows укажите дополнительную папку. Можно искать только в ней, оставив поле образа пустым.
5. Нажмите «Начать поиск». Выберите запись для предпросмотра и двойным нажатием откройте файл. Кнопка «Остановить» сохраняет уже записанные результаты.

Для проверки без личных данных выберите `demo/demo.img`. Программа должна найти одну фотографию, один исправленный JPEG и одну EXIF-миниатюру. Эталоны лежат в `demo/originals`. Для проверки разрозненных JPEG выберите `demo/deep/fragments.img`, включите «Собирать разрозненные JPEG и PNG», задайте сектор 512 байт и окно 1 МиБ. Эталоны для этого образа лежат в `demo/deep/originals`.

Если фото были удалены недавно, прекратите запись на исходный накопитель. Не запускайте на нём CHKDSK, не устанавливайте на него приложение и не сохраняйте туда результаты. Если носитель нестабилен, используйте инструмент снятия образа с картой ошибок или профильную лабораторию. В этой версии для работы с секторами нужен уже снятый образ.

## Что ищет приложение

| Источник | Реализованный метод |
| --- | --- |
| NTFS | Удалённые MFT-записи, резидентные данные, чтение разнесённых кластеров по сохранённым runlists, резервная запись MFT, карта занятости при наличии читаемого $Bitmap |
| FAT32 | Удалённые короткие имена; первая буква заменена символом `_`. Пробует сохранившуюся цепочку FAT и предполагаемое непрерывное размещение |
| exFAT | Удалённые наборы записей, имена Unicode, флаг непрерывного размещения и карта занятости при наличии |
| Секторы образа | Сигнатуры JPEG, PNG, WebP, проверка структуры и декодирование. Охватывает занятые и свободные области |
| Разрозненный JPEG | Дополнительный режим подбора двух фрагментов с одним промежутком; с картой ddrescue также проверяет соединение трёх известных прочитанных диапазонов. Проверяет таблицы Хаффмана, порядок restart-маркеров, точное количество MCU, границы коэффициентов и заполнение битов в конце скана |
| Карта ddrescue | Из образа берутся только диапазоны со статусом `+`. Другие участки и промежутки вне карты исключаются из источников результата |
| Повреждённый JPEG | EXIF-превью, добавление маркера EOI при известной длине; частичное извлечение до длинной обнулённой области внутри первого скана |
| Папка с копиями | Существующие JPEG, PNG и WebP, а также поиск вложенных JPEG, PNG и WebP в сохранённых `thumbcache_*.db` с сигнатурой CMMM. Для Windows это обычно файлы из `%LOCALAPPDATA%\Microsoft\Windows\Explorer` |

Извлечённые файлы делятся по типу результата. «Декодируется» означает, что декодер смог прочесть файл. Например, повреждённый JPEG всё равно может декодироваться с артефактами. «Часть кадра JPEG» означает, что файл содержит сохранившийся байтовый префикс и добавленный маркер конца. Рендер этого файла может показывать недостающую часть сплошной заливкой. Дубликаты по SHA‑256 учитываются в журнале и сохраняются один раз. Программа пишет исходные смещения, способ извлечения и хешы. Для результатов восстановления по имени проверяйте занятость кластеров, способ определения адресов и сам кадр.

## Режим для разрозненных JPEG и PNG

Режим самостоятельной сборки анализирует однопроходные 8‑битные baseline JPEG с уцелевшим заголовком и маркером конца. Основной поиск JPEG проверяет два фрагмента в порядке их расположения в образе. Дополнительные варианты включают разрыв, занятый другим JPEG или BMP, и три части JPEG с переставленной серединой и концом, когда область заканчивается длинным однообразным заполнением. Стыки находятся на заданной границе относительно начала файла. Размер обычно совпадает с размером кластера исходной файловой системы, а для искусственных образов может быть задан размер сектора. Чем больше окно, тем больше потенциальное расстояние между фрагментами и время проверки. Поиск ограничен числом концов файла, разрывов и вычислительным бюджетом на один заголовок. В журнале отмечается, если этот бюджет исчерпан.

Собранные JPEG лежат в `assembled_jpeg`. Если найдено несколько различных вариантов, они помечаются как неоднозначные и пишутся в `ambiguous_jpeg`. Сохраняется до восьми вариантов на заголовок. Структурная проверка отсеивает многие неверные стыки. Если две последовательности байтов образуют допустимый JPEG, только эталон может доказать, какая была оригиналом.

PNG собирается из двух частей по CRC блоков IDAT и проверке всего изображения. Хвост может физически лежать перед заголовком. Для PNG окно задаёт радиус поиска в обе стороны.

Карту GNU ddrescue указывайте от того же образа. При обычном копировании позиции исходника и образа совпадают. Если образ снят со смещением, передайте в CLI `--map-delta` с разницей между выходной и входной позицией в байтах. Карта помогает пропустить физически нечитаемые диапазоны, даже если в файле образа в этих местах сохранились старые байты от предыдущей записи. Образ и карта открываются для чтения.

## Проверка и сравнение

Команды для PowerShell из распакованной папки после первого запуска:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe src\cli.py demo\demo.img .
.\.venv\Scripts\python.exe src\cli.py demo\deep\fragments.img . --no-metadata --deep --search-mib 1
.\.venv\Scripts\python.exe tests\benchmark_fragments.py .\benchmark-run
.\.venv\Scripts\python.exe tests\score.py demo\originals .\recovery-ИМЯ-ПАПКИ
```

`score.py` принимает несколько папок результатов и сравнивает их с известными оригиналами по SHA‑256. `outside_reference` считает уникальные файлы вне набора оригиналов: это могут быть частичные изображения, превью, изменённые файлы или неверные находки. Для честного сравнения с R‑Studio, PhotoRec и UFS Explorer каждой программе дают одинаковый образ и отдельно оценивают точные совпадения, качество частичных результатов, ложные находки и время сканирования. Публичный набор для дальнейшей проверки доступен у [DFRWS](https://dfrws.org/forensic-challenges/).

На комплектном синтетическом наборе обычный поиск дал 1 из 6 уникальных оригиналов по SHA‑256. Режим сборки дал 6 из 6, включая пять разрозненных JPEG. В результате дополнительно было шесть неоднозначных вариантов и четыре частичных файла вне набора эталонов. Один поиск достиг вычислительного лимита. Подробный результат запуска лежит в `demo/deep/benchmark.json`. Этот тест сравнивает два режима приложения. Сравнение с внешними программами требует прогона каждой из них на том же образе.

Отдельный сравнительный прогон на образах NIST описан в [benchmark/REPORT.md](benchmark/REPORT.md). В этой папке лежат эталонные хеши образов и результаты с точными хешами восстановленных файлов.

## Пределы версии 0.3

Лимит отдельного файла настраивается до 256 МиБ, лимит изображения 40 млн пикселей. exFAT и FAT32 проверяются в обычных образах томов и первичных MBR/GPT-разделах. Эта версия пропускает NTFS-файлы со сжатыми, разреженными или зашифрованными потоками, и сложные случаи, где список экстентов вынесен в дополнительные записи. Произвольный порядок фрагментов, сборка progressive JPEG, восстановление HEIC и RAW камеры, чтение E01/VHDX, APFS и ext4, съём образа с проблемного диска и аппаратные методы чтения пока отсутствуют. Расширенный поиск на основном объёме терабайтного диска может быть медленным. Сборка ограничена доступными данными образа.

При полном замещении видимых секторов прежняя фотография может сохраниться в независимой копии, превью, резервной области или снимке. Профессиональные комплексы вроде PC‑3000 на отдельных поддерживаемых устройствах получают доступ к данным, скрытым за обычным интерфейсом накопителя. Успех зависит от модели, контроллера и от того, сохранились ли старые данные и ключи. Аппаратные комплексы, платные версии и случаи, требующие физического чтения, не входят в опубликованный прогон.

### Приоритеты развития

1. Съём образа с картой нечитаемых секторов и возобновлением чтения.
2. Поиск фрагментов в произвольном порядке, локальное ускорение проверки JPEG, журналы и резервные копии метаданных, сравнение на независимых наборах.
3. HEIC, DNG, CR2, CR3, NEF, ARW. Поиск вложенных превью в RAW-контейнерах, кешах и экспортированных резервных копиях, сопоставление уменьшенных копий с оригиналами.
4. Источники лабораторий. Импорт полученных легальным штатным способом дампов и карт ошибок. Обработка дампов сырого NAND требует формата и схемы конкретного контроллера, коррекции ошибок, реконструкции отображения физических страниц и, при наличии шифрования, соответствующих ключей.
